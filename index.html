Gabarito comentado

Professor: o objetivo do gabarito é orientar a correção. Existem outras implementações válidas quando o aluno consegue justificar suas decisões.
1. Cadastro de Produtos
public class Produto
{
    public int Id { get; set; }
    public string Nome { get; set; } = string.Empty;
    public decimal Preco { get; set; }
    public int QuantidadeEstoque { get; set; }
}

public class AppDbContext : DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options)
        : base(options) { }

    public DbSet<Produto> Produtos { get; set; }
}

O DbContext representa a sessão de trabalho com o banco. O DbSet representa o conjunto de Produtos consultado e persistido pelo EF Core.

2. Validações
[Required]
[StringLength(100, MinimumLength = 3)]
public string Nome { get; set; } = string.Empty;

[Range(0.01, double.MaxValue)]
public decimal Preco { get; set; }

[Range(0, int.MaxValue)]
public int QuantidadeEstoque { get; set; }

No POST, verifique ModelState.IsValid antes de salvar. A validação do servidor continua necessária mesmo que a View tenha validação no navegador.

3. Pesquisa e filtros com LINQ
var query = _context.Produtos.AsQueryable();

if (!string.IsNullOrWhiteSpace(nome))
    query = query.Where(p => p.Nome.Contains(nome));

if (precoMin.HasValue)
    query = query.Where(p => p.Preco >= precoMin.Value);

if (somenteEstoque)
    query = query.Where(p => p.QuantidadeEstoque > 0);

var produtos = await query.ToListAsync();

Os filtros são montados antes da materialização. O EF Core pode traduzi-los para SQL e executar o filtro no banco.

4. Regra de estoque
var produto = await _context.Produtos.FindAsync(id);
if (produto == null) return NotFound();

if (quantidade <= 0)
    return BadRequest();

if (produto.QuantidadeEstoque < quantidade)
{
    ModelState.AddModelError("", "Estoque insuficiente.");
    return View(produto);
}

produto.QuantidadeEstoque -= quantidade;
await _context.SaveChangesAsync();

Não permitir estoque negativo é uma regra de negócio e precisa ser protegida no servidor.

5. Categoria 1:N Produto
public class Categoria
{
    public int Id { get; set; }
    public string Nome { get; set; } = string.Empty;
    public ICollection<Produto> Produtos { get; set; } = new List<Produto>();
}

public class Produto
{
    public int Id { get; set; }
    public string Nome { get; set; } = string.Empty;
    public int CategoriaId { get; set; }
    public Categoria? Categoria { get; set; }
}

CategoriaId é a FK. Para trazer os dados relacionados, uma consulta pode usar .Include(p => p.Categoria).

6. Clientes e Pedidos

O relacionamento esperado é Cliente 1:N Pedido. Pedido possui ClienteId e a navegação Cliente. Para detalhes do cliente, pode-se consultar Cliente usando Include(c => c.Pedidos).

7. Biblioteca

Ao emprestar, consulte o Livro, verifique Disponivel, crie o Emprestimo e altere o Livro para indisponível. Na devolução, preencha DataDevolucao e torne o livro disponível novamente.

8. Dashboard
TotalLivros = await _context.Livros.CountAsync();
TotalAlunos = await _context.Alunos.CountAsync();

EmprestimosAtivos = await _context.Emprestimos
    .CountAsync(e => e.DataDevolucao == null);

Recentes = await _context.Emprestimos
    .Include(e => e.Aluno)
    .Include(e => e.Livro)
    .OrderByDescending(e => e.DataEmprestimo)
    .Take(5)
    .ToListAsync();

Um DashboardViewModel é apropriado porque a tela reúne dados agregados de entidades diferentes.

9. Service + DI
builder.Services.AddScoped<EmprestimoService>();

A regra de empréstimo pode sair do Controller e ir para EmprestimoService. O fluxo fica: Controller → Service → DbContext → SQL Server.
